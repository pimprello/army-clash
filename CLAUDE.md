# Notes for Claude

This repo auto-posts Army Clash Shorts to YouTube for Rellz (the battle is paced to end close to 60 s and the video ends 3 s after it, `rules.video`). `.github/workflows/post-army-clash.yml` renders with `render.js` + `engine.js` and uploads with `upload.js`. It posts four Shorts a day, at 10am, 2pm, 6pm and 10pm London time (`rules.schedule`; Rellz asked for 4 a day on 2026-11-08): the workflow wakes every 10 minutes around each slot and `slot.js` lets only the first run in a slot post. A manual run (Run workflow) always posts. There is no self-queuing any more. If an upload fails, the reason is shown as a GitHub annotation (readable via the check-runs annotations API).

When Rellz asks to change future videos ("add a unit", "use these colours", "make X rarer"):
1. Prefer editing `rules.json`. Add a new rule there if the request is a dial he'll likely want to turn again, then document it in `RULES.md`.
2. For new behaviour, change `engine.js` (simulation and drawing) or `render.js` (rules, titles, tags). Keep old seeds deterministic when a new option is off.
3. Test before pushing: `npm ci`, then render one frame or a full video with `SEED=123 node render.js` (needs ffmpeg), and check balance across many seeds for gameplay changes.
4. Don't send Rellz preview videos (he asked not to; they take too long). Test with still frames instead.
5. Commit and push to `main`. The next run checks out `main`, so the change applies from the next video. Say plainly that already-posted videos don't change.

Line-ups, formations and maps rotate deterministically from the number of rows in `uploads.md`. Every second video (`rules.creative.every`) is instead a creative match-up invented from the video's seed by `creative.js` and balanced on the spot with quick test battles (`sim-worker.js` runs them in parallel). With `rules.combat` on (intelligent combat: melee moves, fewer bullets, roster cards), every 1v1 video is also tuned on the spot (`creative.tune`), starting from the last tuned size of that line-up and mode in `videos.jsonl`; battle modes (`rules.modes`) and skins (`rules.skins`) roll their own dice in `render.js`. With `rules.tribes` on, each army is made of tribes (their own dice, `seed ^ 0x7121BE`) whose stories come from past videos (`chronicle.js` reads `videos.jsonl`); with `rules.tribes.evolve` their upgrades go to weapon tier 5 (tier 4 = an element, its own dice `seed ^ 0xE7017E`) and each shows on the troops and on a card. Every video gets a thumbnail (`rules.thumbnail`, `drawThumb` in `engine.js`, `out/thumb.jpg`); `upload.js` sets it, and a refusal (Shorts need the Partner Program) is only a warning. After changing any overlay (roster card, tribes panel, story, outro line), run `node check-layout.js`: it must pass. The layout is `rules.ui` (2 = the Shorts-safe layout: keep everything clear of YouTube's buttons and title; the layout check enforces it). World events (`rules.world`: glitch, flip, mirror, blackout, time stop, blood moon, supersize, rave) roll their own dice (`seed ^ 0x3E1D7A`) and must hit both sides alike. Battle events (airdrops, airstrikes, meteors) use their own dice (`setupEvents`), and the cinematic `Director` in `engine.js` only changes the camera and pace: the battle plays out the same with or without it (the simulation always moves in fixed 1/120 s ticks).

A daily scheduled autopilot run follows `AUTOPILOT.md` (health check, learn from `stats/summary.md`, add one new thing, log it in `CHANGELOG.md`). Keep that file's guardrails in sync with Rellz's instructions, and log manual changes in `CHANGELOG.md` too.

Limits to remember: Rellz wants 4 uploads a day (never raise it without him asking; each upload costs 1,600 of the project's 10,000 daily API units); YouTube allows 100 API uploads a day per project, and the repo must stay active (each upload commits to `uploads.md`).
